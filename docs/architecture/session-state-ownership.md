# Session State Ownership

OpenClaw session data remains file-backed. This model makes ownership explicit so the current `sessions.json` shape can keep working while new code uses typed boundaries.

## State layers

- **Identity** is the stable key and routing identity for a session: agent id, channel/user/group references, labels, and thread parentage.
- **Durable state** is the authoritative persisted data needed after restart: transcript references, user-selected model/auth/runtime overrides, lineage, plugin extension state, ACP metadata, and explicit lifecycle history.
- **Derived projection** is display or diagnostic data computed from durable state, transcript manifests, runtime registries, or gateway context. Minimal and display projections must not require heavy transcript scans.
- **Runtime/ephemeral state** is active-run evidence that must be reconciled against live runtime registries before it is treated as authoritative. Persisted `status: running` is a recovery hint, not proof of a live run.

## Non-goals

- No SQLite migration in this architecture step.
- No destructive data migration, deletion, or rewrite of user session data without a dry-run, backup, or explicit compatibility path.
- No removal of legacy or case-insensitive session key alias resolution until compatibility tests prove it is safe.
- No plugin ability to write arbitrary core-owned `SessionEntry` fields through extension slots.

## Projection tiers

- **Minimal**: session key, session id, update time, identity kind, agent id. It excludes transcript preview, plugin extension payloads, ACP metadata, and diagnostics.
- **Display**: minimal plus labels, channel display fields, status, and last interaction time. This is the Gateway list-view hot path when transcript previews are not requested.
- **Details**: display plus transcript reference, parentage, selected runtime/auth/model overrides, and usage totals.
- **Diagnostic**: details plus plugin/ACP/debug/heartbeat/compaction/system-prompt diagnostics.

## Retention classes

Retention class mapping starts as a typed compatibility layer and does not change cleanup behavior by itself.

- **human-facing**: default direct/group/channel/thread sessions; preserved by default.
- **subagent-run**: subagent runtime sessions; cleanup eligible only through explicit retention policy.
- **cron-run**: isolated cron execution sessions; cleanup eligible only through explicit retention policy.
- **heartbeat**: synthetic heartbeat sessions and heartbeat state; cleanup eligible only through explicit retention policy.
- **plugin-runtime**: plugin-owned runtime or ACP sessions; extension data is preserved unless an owner-specific policy says otherwise.
- **archive**, **diagnostic**, **unknown-legacy**: preservation-biased until reconciliation explains a safe action.
